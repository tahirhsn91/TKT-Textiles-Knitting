# Database

## migrations/
SQL migration files generated by Drizzle Kit from the schema in `backend/src/db/schema/`, via `backend/drizzle.config.ts`.

To check whether a target database (e.g. production) is missing any migrations, point `DATABASE_URL` at it and run a dry push — it prints the diff and asks for confirmation before applying anything:
```bash
cd backend
npm install
DATABASE_URL=<target-db-url> npm run db:push
```

After changing `backend/src/db/schema/`, generate a new versioned migration file (does not touch any database):
```bash
cd backend
npm run db:generate
```

## backup.sql
Full `pg_dump` of the database at the time of export (includes schema + all data).

To restore to a fresh PostgreSQL instance:
```bash
psql postgresql://postgres:password@localhost/heliumdb < database/backup.sql
```

When using `docker compose up`, the backup is automatically loaded into the postgres container on first startup via the `docker-entrypoint-initdb.d` mount.
