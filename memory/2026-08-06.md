## Operator production-based salary (branch: feat/operator-production-salary — NOT merged)

Grilled the user extensively (grill-me) on a new calc for **dept 0002 "Operator"** employees.

### Agreed spec
- Scope: ONLY Operator (0002). Other departments keep attendance formula.
- Per-row value = `netWt × machine.makingRate` (Fabric Production transactions, transactionType code "Fabric_Production"). Skip null/zero netWt; quantity ignored.
- Group by (employee, calendar date) within selected month [1st→last day].
- Present days = distinct dates with ≥1 production row. Zero-production operator → present 0 / salary 0 (row still shown).
- Per-day credited = `max(daily production sum, operator's daily basic salary)`. **Operator baseSalary is a DAILY wage** (not monthly — key fact). Null/0 basic → daily basic 0 → credited = production.
- Total Salary = Σ per-day credited, rounded to 2 decimals.
- Endpoint returns aggregate (presentDays, totalSalary) + per-day breakdown, later extended to machine level.
- Frontend overlays present + totalSalary onto operator rows; Present + Total Salary read-only; Total Attendance = Present + Holidays (informational); OT/Allowances/Deductions unchanged; Att. Allowance rule unchanged; validation unchanged.
- Save computed values as normal salary_detail (no schema change).
- Apply for any selected month/year (deterministic).
