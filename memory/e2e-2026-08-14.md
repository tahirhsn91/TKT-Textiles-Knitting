### 🔴 BUG #1 — Advances list month/year filter 500 (date column LIKE)
- GET /api/employees/advances -> 200 works. GET ?month=8&year=2026 -> **500 {code:42883}**. GET ?year=2026 -> 500.
- ROOT CAUSE: `backend/src/routes/employees.ts` GET /employees/advances uses `like(employeeAdvancesTable.date, ...)` but `employee_advances.date` is Postgres **date** type (migration #0016). `LIKE` doesn't exist on date -> PG 42883 (undefined_function).
- UI impact: Advances page "Advance History" (defaults Aug 2026) fires this -> 500, history fails to load. BROWSER CONSOLE: three 500s at 22:30.

### 🔴 BUG #2 — Axios customFetch sends JSON string body w/o Content-Type: application/json (400s + empty bodies)
- POST /api/validate/daily-list from browser -> **400 "Invalid option: expected one of production|receipt|delivery"** even though body is valid `{"operation":"production",...}`.
- ROOT CAUSE: `customFetch` passes `body` as a JSON **string** (call sites `JSON.stringify(...)`). axios does NOT auto-set `Content-Type: application/json` for string bodies. Captured browser header: `Content-Type: application/x-www-form-urlencoded` -> Express json parser ignores body -> req.body empty -> zod validateBody sends 400. (Node tests sending application/json got 200 — hence missed by API tests.)
- AFFECTED (no Content-Type, BROKEN): use-daily-production.ts (POST/PUT/cancel 146/162/209), lib/plausibility.ts (42/86/110), payroll-entry.tsx (590/591 salary POST/PUT), import-dialog.tsx (341/360), advances.tsx:145 + employees/index.tsx:165 (advances POST).
- NOT affected (set Content-Type): use-daily-deliveries.ts (144/155), use-yarn-receipts.ts (191/204), generated api.ts masters (explicit JSON).
- FIX (Option B): in `frontend/src/lib/http-client.ts` request interceptor, set `Content-Type: application/json` for POST/PUT/PATCH when body present and header not already set. Central, fixes all consumers.
- NOTE: masters browser create WORKED because generated api sets Content-Type explicitly.
