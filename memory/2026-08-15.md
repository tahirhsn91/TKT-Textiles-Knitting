# 2026-08-15

## Hot reload fix (dev stack was running prod config)

- **Issue:** User reported hot reload not working in the dev environment.
- **Root cause:** The dev stack (`tkt-textiles-knitting-*`) was started with **only `docker-compose.yml`** (the production file). Inspect labels confirmed both `frontend` (nginx, port 80) and `backend` (`node dist/index.js`) were built/served from prod config — no Vite, no `tsx watch`, no source mounts.
- **Fix:** Rebuilt with the documented dev override and restarted:
  - `docker compose -f docker-compose.yml -f docker-compose.dev.yml build frontend backend`
  - `docker compose -f docker-compose.yml -f docker-compose.dev.yml down`
  - `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`
- **Result:** frontend = Vite dev server (HMR) on `0.0.0.0:3001->3000`; backend = `tsx watch`; postgres healthy with data persisted (named volume `tkt-textiles-knitting_postgres_data`).
- **Verified:** frontend HTTP 200, `/api/healthz` HTTP 200, and live source mount (a file written to host `frontend/src/` appears inside container at `/app/src/`).
- **Lesson for future:** If dev hot reload is broken again, check `docker inspect <frontend/backend container> --format '{{.Config.Cmd}}'` — if it shows `nginx` / `node dist/index.js` instead of `npm run dev`, the stack was started without the dev override. Restart with both compose files.
- **Lesson: tsx watch can serve stale code after a git pull/merge.** After the net-weight merge, `tsx watch` logged a restart but the running process still served OLD code (new API field absent). A clean `docker restart <backend container>` is the reliable fix. Verify an API change actually landed by hitting the endpoint (don't trust the "Restarting..." log alone).

## Dev frontend crash-loop / esbuild EPIPE fix (12:10-12:40Z) — PR #173 OPEN
- **Symptom:** User couldn't access the dev app; `localhost:3001` connection failures, then intermittent `Internal server error: The service is no longer running: write EPIPE`.
- **Two root causes:**
  1. **OOM crash-loop:** Base compose caps frontend at **256 MB** (issue #21, for static nginx prod), but dev runs **Vite** which exceeds 256 MB → SIGKILL → crash-loop (RestartCount 89). Also corrupted `.vite/deps` cache (stuck `deps_temp_*`).
  2. **esbuild EPIPE disconnects:** Even at 512 MB, Vite's esbuild transform service intermittently died with `write EPIPE` — known Vite-in-Docker issue on bind mounts/overlay FS where inotify event storms kill the esbuild service. Confirmed esbuild binary itself healthy (20/20 transforms).
- **Fix (PR #173, `fix/dev-frontend-oom`):** (a) `docker-compose.dev.yml` dev frontend `mem_limit: 512m` / `mem_reservation: 256m` (prod stays 256m); (b) `frontend/vite.config.ts` adds `server.watch.usePolling: true` to stop the EPIPE disconnects. Cleared corrupt `.vite` cache.
- **Verified:** previously-failing files (`api.schemas.ts`, `dropdown-menu.tsx`) → 200; rapid multi-module + repeated edits → 200, 0 EPIPE, HMR live; Running=true RestartCount=0 (512 MB); all containers healthy.
- **Lessons:** Vite dev needs >256 MB (raise in DEV override only). Vite-in-Docker esbuild `write EPIPE` → `server.watch.usePolling:true`. Corrupt `.vite/deps` persists in anonymous `/app/node_modules` volume across container recreations — clear manually (`docker run --rm -v <vol>:/nm alpine rm -rf /nm/.vite`).
- **Status: PR #173 OPEN** (not yet merged as of this flush).
